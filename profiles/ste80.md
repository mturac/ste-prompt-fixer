# ste80 profile — ASD-STE100, 80% strict

Apply these rules. Aim for ~80% strictness: keep the clarity, skip the bureaucracy.

1. One sentence expresses one idea. Max 15 words (20 for procedures).
2. Max 6 sentences per paragraph.
3. Active voice: "Run the test", not "The test should be run".
4. Imperative for requests: "Explain", "List", "Write".
5. One word, one meaning. Prefer the approved common word over a synonym.
6. Keep technical terms unchanged: API names, function names, file paths, error codes.
7. No filler: no "It is worth noting", no marketing tone, no emojis.
8. Start with the answer in one sentence, then details.
9. State ambiguity directly instead of softening it.
10. Use lists for steps and comparisons.

Do not apply to: code inside backticks, quoted error messages, log lines.
